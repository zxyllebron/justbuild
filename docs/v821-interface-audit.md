## 当前可执行的重新设计方案

现在已绑定真实 STEP，可基于对应实体包围盒与真实安装孔重新设计。没有配套插头/线缆/动作数据时，可做明确标注为设计参数的保守服务窗口，并检查静态实体与窗口几何；不能声称已验证实际插拔、弯线、声学或射频性能。

1. 保持单板、上下盖结构；PCB 安装点来自原始板孔，不用合成参考孔。锁盖紧固可以独立布置，但要标明其用途并避开所有接口、线束、器件和天线禁布区。
2. 左侧集中处理 USB、SD、CARD2；以实际接口口面、卡机构和插头尺寸决定开口，而非按外观把三个口做成一个大洞。
3. KEY 保留壳外按压；FEL、ADB、4G 开关保留维护访问，分别定义动作方式、工具和行程。维护盖/操作件必须可拆、可复位，不能依赖拆 PCB 才能操作。
4. CAM/FPC、MIC/SPK 和同轴座按内部装配优先设计，提供锁扣/扣合操作、线路全路径与合壳时的防夹线空间。相机、屏、麦克风、扬声器、天线位于壳内还是壳外会改变外壳结构，必须先确认。
5. UART3、相邻 TX/RX/GND、顶部排针和 3V3 排针逐项确定使用频率。可合并一个可拆维护盖，但不能合并清单或丢失任何接口的独立证据。
6. STEP 名称已将 U-01/U-02/U-03 分别解析为 BUZZER1、AIR780E 模块 U6、晶振 X2；实际背面完整性和配套外设仍需核对。热/RF/声学无资料时相应检查保持 `not_checked`；不能因为 CAD 实体有效就宣布整机可用。

## 对当前候选生成和确认流的代码审查

审查文件：`src/justbuild/inspection.py` 与 `src/justbuild/web/app.js`。本次未修改它们。

### 当前行为与漏检原因

- `inspection.py:33-40` 为每个实体建立包围盒，选最大薄 XY 实体作 PCB。未解析命名、BOM、丝印、外设功能、正反面语义；旋转板和有些合并实体不能据此可靠识别。
- `inspection.py:60-72` 把每个非 PCB 实体当一个访问候选，仅按距四个 XY 板边是否小于 2 mm 决定 `external` 或 `internal`。这不是接口识别：一个插座由多个 STEP 实体组成会产生多项；合并成单个实体又可能丢失多项。中部 KEY/FEL、开关、CAM、同轴座和调试排针无法因此得到正确的操作/维护需求。
- `inspection.py:73-91` 只会自动生成 XY 侧面的矩形口和通用直线服务包络，不能自动表达壳顶按钮、按钮传力/复位、拨柄扫掠、卡座翻盖、FFC 锁扣、同轴垂直扣合、弯线、声路和天线禁布。
- 通用的 25 mm 服务包络明确为未核实默认值，不是任何真实插头或手指的测量证据，不能进入“接口完整且能用”的结论。
- `inspection.py:102-104` 初始将完整性标志设为 false，这是合理的；但 `web/app.js:54` 的总确认按钮直接把安装孔、接口、禁布三项完整性全设成 true。用户无法通过确认一个未知实体清单，补出系统根本没有识别的按钮、配套插头和背面器件。

### 建议主控实现的修正

1. 新增功能清单（例如 `functional_features`）层，和 `ports` 的开口几何层分开。一个功能件可关联多个 STEP 实体，一个实体也可关联多个操作要求；记录 `source`、丝印/料号、类型、访问模式、匹配实体、板面/方向、未解决项和审阅状态。
2. 对照图片/BOM/接口说明的功能件清单与 STEP 实体清单，双向检查孤立项。STEP 仅有裸板时允许识别孔位，但接口完整性必须为未完成；不能把“没有额外实体”当“没有接口”。
3. 增加 `button_press`、`switch_sweep`、`card_service`、`connector_mating`、`latch_sweep`、`cable_route`、`acoustic_path`、`rf_keepout` 等动作/约束类型。先声明哪些动作有真实几何、哪些检查器尚不支持；不支持的必需项阻止可打印放行。
4. 确认页面展示逐项默认访问方案和未解决项。总确认只能确认已完整、逐项可审阅的方案，不能同时把 false 的完整性旗标无条件改成 true。未知用途、未绑定 STEP、缺必需动作尺寸、背面缺失都应保持待补。
5. 将“孔轴对齐”“裸板与壳无碰撞”“已声明插头可插入”“全部功能访问完整”分别报告。前三者成功不能推出第四者成功。
6. 主控现在可用真实 STEP 映射制作访问草案并重新建模。依旧禁止把旧合成板参考 3MF 改名包装成真实板新版；新产物必须绑定本次源文件哈希与具体窗口设计参数。
